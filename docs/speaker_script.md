## Spoken script and visual cues

### 1. Opening — Aryanraj

“We are Team 10. We study whether Differential Evolution can improve the training recipe of an EfficientNet-B0 tomato classifier. We built the optimizer, the evaluation pipeline, and an offline interface for inspecting predictions and search behavior. Our guide is Manoj Kumar S, Assistant Professor.”

### 2. Define the optimization problem — Aryanraj

“An optimization problem has decisions, an objective, and constraints. Our decisions include learning rate, regularization, head width, and fine-tuning depth. The objective is validation macro-F1. A candidate costs an actual training run, and this mixed recipe cannot be optimized directly by differentiating the validation score.”

### 3. Explain population search — Aryanraj

“A population maintains several possible solutions. Variation explores new recipes, while selection retains useful ones. Exploration seeks new regions and exploitation refines promising ones. DE uses numerical differences between candidates to propose steps. Its operators are inspectable, but it does not guarantee a global optimum.”

### 4. Locate DE within the field — Aryanraj

“GA, DE, and evolution strategies are evolutionary methods. PSO, ACO, and ABC are swarm methods. Simulated annealing uses a physics analogy; BBO uses biogeography. Categories overlap. We judge mechanisms and measured behavior, not the metaphor. In particular, binomial crossover makes the full DE algorithm coordinate-dependent.”

Handoff: “Richik will explain the data and the baseline fixed before search.”

### 5. State the application and scope — Richik

“The fixed application is the color tomato subset of PlantVillage. The cleaned count on the slide comes from the preparation output. Exact duplicates are removed and perceptually similar groups stay in one split. These controlled leaf images support reproducible evaluation, but they do not establish performance on arbitrary field photographs.”

### 6. Trace the evidence flow — Richik

“Follow the pipeline from verified images to the fixed baseline, DE and random search, validation reranking, repeated final training, and the locked test. Both searches use equal candidate budgets and the same proxy conditions. Final recipes are frozen before test evaluation. The demo loads the exact seed-zero checkpoints.”

Point to the baseline path and the separate reranking paths. Do not imply that the baseline is selected by reranking.

### 7. Explain the registered baseline — Richik

“The baseline freezes EfficientNet-B0 and trains a 256-unit head with dropout 0.2, Adam at 0.001, and no weight decay or label smoothing. It uses the common crop-and-flip pipeline without extra RandAugment. Candidate recipes use AdamW. Therefore, the baseline comparison concerns the whole recipe; DE versus random search more directly compares proposal strategies.”

Handoff: “Suraj will explain the operators and the seven decisions they evolve.”

### 8. Walk through the DE operators — Suraj

“For each target, choose three distinct donors, all excluding that target. Mutation adds F times a donor difference to the third donor. Repair an out-of-range coordinate between its parent and violated bound. Binomial crossover takes mutant coordinates with probability CR and forces at least one mutant coordinate. Selection accepts an equal or better validation score.”

Point to the operator example. “We test these invariants directly. Each completed evaluation persists the population and random-generator state so an interrupted run can resume.”

### 9. Decode the chromosome — Suraj

“All seven genes lie between zero and one. Learning rate and weight decay decode logarithmically; head width, unfreezing depth, and augmentation are discrete. A zero-width head is a direct linear classifier. Augmentation zero disables extra RandAugment, retaining the common crop-and-flip transforms. Population, F, CR, and the evaluation budget are fixed before search.”

Point to the two logarithmic rows and the printed budget; avoid reading every bound aloud.

### 10. Distinguish search fitness from final performance — Suraj

“This is proxy validation macro-F1 against candidate evaluations. Both searches use a fresh pretrained model, a shared training seed, and the same fixed subset. Their top three distinct recipes are reranked at full resolution using validation only. Discuss the actual curves, including random-search advantages or ties; a proxy winner need not be the final test winner.”

If search is still running: “This is a partial search trace. The planned budget and final comparison are not complete.”

### 11. Read the measured comparison — Suraj

“The displayed means and standard deviations cover all three registered training seeds. Compare baseline and DE accuracy and macro-F1, then relate them to the random-search control in the full results. Relative error reduction is signed: a negative value means more error. We do not substitute the best seed or a search score.”

Read the current values and state the observed direction. Do not invent a winner or significance claim. If the final artifact is absent, say: “These held-out results remain pending.”

Handoff: “Sushant will show where the models succeed, fail, and disagree.”

### 14. Inspect Grad-CAM explanations — Sushant

### 17. Explain the metrics — Sushant

“Accuracy counts correct labels. Precision, recall, and F1 are calculated per class and macro-averaged. ROC-AUC measures ranking. Calibration asks whether confidence matches correctness, and latency measures the specified forward pass. These metrics answer different questions; none alone proves readiness for field deployment.”

### 18. Explain uncertainty and paired evidence — Sushant

“These confidence intervals use one thousand deterministic bootstrap resamples of seed-zero predictions. They describe resampling uncertainty on this split, not differences across farms. Exact two-sided McNemar compares paired correctness on the same images. Read its disagreement counts and p-value; statistical significance is not effect size. Three-seed variation was reported separately.”

If evaluation is unfinished, the intervals and paired test remain pending. Do not replace them with training or validation variation.

Handoff: “Richik will separate optimizer validation from classifier evaluation and explain the computational cost.”

Curves show median best-so-far error with interquartile spread. This tests the optimizer independently of the expensive CNN objective.”

### 20. Read the median table — Richik
